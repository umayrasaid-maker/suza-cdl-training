# CDL Training Hub | State University of Zanzibar

A responsive website with public course listings, registration, announcements, downloadable poster generation, and an administrator dashboard, using Flask and SQLite.

## Start locally

```bash
cd cdl_training_website
python3 -m pip install -r requirements.txt
export ADMIN_KEY='choose-a-long-unique-private-password'
python3 app.py
```
Open http://127.0.0.1:5000.

## Features
- 26 training sessions loaded from the supplied CDL Training Programme, dated 27 November 2026 through 15 October 2027.
- Date, audience, keyword, and availability filters.
- Individual registration by full name, email, phone, role and university unit. Each email can register once per training. Server-side capacity validation.
- Admin: private key, registration overview, CSV export, change session availability, capacity and venue, publish announcements.
- Square PNG training poster designer and print option.
- Academic-calendar pause dates displayed on the public site.

## Programme scheduling decisions
All advertised workshop slots have been set to **Friday 2:00–4:00 PM (East Africa Time)** as requested. The supplied programme includes several workshops intended to last 3 or 4 hours. Their `original_hours` are preserved in the database, but their content/duration should be revised or arranged separately before each is announced. Four five-day quarterly intensives are mentioned in the programme introduction but lack dates and session details, so they have **not been invented or published** on the website. The programme document indicates no meals.

## Official branding
The official CDL logo was **not included in this uploaded PDF**. No replacement logo was fabricated. For posters, place the original, unaltered logo image at `static/cdl-logo.png`. The header currently uses styled CDL text, not a purported official crest.

## Deployment and security
This is a usable starting implementation, not a deployed public website. Host it on a HTTPS-enabled Python/WSGI host (e.g. a managed university server) and configure `ADMIN_KEY` as a strong secret environment variable. Use a secure reverse proxy, backups, rate limiting, anti-spam measures, monitoring, privacy notice, and institutional data retention rules before opening registrations to the public. A shared administrator password is convenient for initial setup but should be replaced with proper per-user authentication and authorization for production. `data/cdl.sqlite3` holds personal registration details and should never be published or committed. Registration submission records entries in the database; the app does **not** send confirmation emails yet. The admin key is kept only in browser memory, not local storage.

## API
GET `/api/trainings`, GET `/api/announcements`, POST `/api/register`. Admin endpoints require `X-Admin-Key`: GET `/api/admin/registrations`, GET `/api/admin/export.csv`, PATCH `/api/admin/trainings/<id>`, POST `/api/admin/announcements`.

## Render deployment (persistent paid instance)
The included `render.yaml` is a Render Blueprint. It specifies a **Starter** instance and a persistent disk for the SQLite registration database; this is not a free deployment. Do not choose an ephemeral free web service for collecting registrations because database changes could disappear on restart or redeploy.

1. Upload this folder to a **private GitHub repository** (exclude `data/*.sqlite3`).
2. In Render, choose **New > Blueprint** and connect the repository. Render will read `render.yaml`. Review the paid service and disk costs before approving.
3. In Render's service environment settings, securely manage `ADMIN_KEY` (auto-generated by Blueprint); use this for the website admin dashboard, and never publish it.
4. Deploy and test a registration, admin access and CSV export. Establish backups and spam controls before sharing the URL publicly.
5. For SUZA domain, have university IT configure the DNS after the Render address works.

The app uses Gunicorn on Render, via `startCommand`. Public visitors do **not** need accounts.
